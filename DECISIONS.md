## 2026-10-02 — Project setup (pre-M0)

**Q: Technology stack?**
A: Python 3.12 + Pydantic v2 (record schemas) + SQLite/JSONL (storage) + YAML configs +
pytest. Local model serving via Ollama behind a swappable `LLMClient` interface with
fixed settings and disk caching. FastAPI reserved for M7 briefs; M1 transparency page
is rendered to static HTML instead of served (simpler, no running process; revisit at M7).
Why: mature, free, file-based auditability. Alternatives rejected: TypeScript (weaker NLP
ecosystem), LangChain (hides audit trail), PostgreSQL (zero-ops not needed yet).

**Q: Budget constraint.**
A: Zero recurring cost. Collection via RSS/Atom, GDELT (free, keyless), official records.
No paid news APIs, no paid LLM APIs. Local open-weight models only.
Consequence: model quality at M4–M6 may lag paid APIs; gold-set scores will quantify the
gap. The anchor-every-claim-to-a-span design compensates.

**Q: Hardware?**
A (measured 2026-10-02 on the build machine): Apple M5, 16 GB unified RAM, Metal 4.
Ollama 0.x installed; one local model present: `gemma4:26b` (~18 GB on disk).
Consequence: 16 GB RAM limits comfortable local inference to ~7B–9B quantized models
for batch use; a 26B model will swap heavily. Final model choice deferred to benchmarking
(see below), not made at setup.

**Q: Which model?**
A: Not hard-coded. At M0 we inventory what is locally available; the actual choice is made
by benchmarking candidate models on the gold set at M4/M5 (claim splitting + neutralization),
per owner adjustment 2026-10-02.

**Q: Reviewers for M0 agreement?**
A: Solo. The gold set is labeled twice in independent blind passes and self-agreement
(Cohen's kappa) is reported. LIMITATION LOGGED: same annotator twice means agreement is
inflated vs. two humans; treat kappa as an upper bound. If self-agreement scores fall below
0.75 Kappa, the pipeline must pause and add a second human reviewer before proceeding to M2.
A second reviewer can re-run the pass using `docs/labeling-guide.md` without changes to process.

**Q: Working language?**
A: English for v1. Original wording always kept alongside; other languages after M8.

**Q: Event scope for v1?**
A: ~12 recent events spanning three types: hard-fact, numeric, contested.

**Q: Source rules (owner, 2026-10-02)?**
A: Per event: ≥1 primary source where one exists + ≥2 wire or original-reporting outlets.
Excluded entirely: opinion/editorial sections, sponsored content, content farms,
anonymous aggregators. Per source, log whether full text is legitimately retrievable;
never work around paywalls or terms of use.

**Q: Architecture adjustments (owner, 2026-10-02)?**
A: (1) Pipeline is a cached batch process; slow local inference is acceptable.
(2) Small non-generative classifiers may be used for triage and contradiction checks
where they match LLM accuracy; LLM reserved for claim splitting and neutralization.
(3) Claim extraction is extractive-first: every claim must trace to an exact span in its
source passage; unanchored output is rejected.

**Q: Python environment?**
A: Project-local `.venv` inside the workspace (managed-runtime Python 3.12.14 base),
deps: pydantic 2.13.5, pyyaml, pytest, beautifulsoup4, requests. Not the managed runtime
itself, to keep the repo self-contained and reproducible.

## 2026-10-02 — Milestone 1 (Source Registry & Diversity Quotas)

**Q: Source diversity enforcement?**
A: Evaluated via `DiversityChecker` (`src/newsx/registry.py`) against `config/diversity_rules.yaml`.
Each event candidate set is strictly validated for:
- Minimum primary sources (mandatory whenever primary exists).
- Minimum secondary sources from independent origins.
- Minimum distinct ownership entities to prevent monopoly narrative bias.
- Minimum distinct geographic regions.
- Zero tertiary aggregators in the core fact base (ratio strictly <= 0.0).

**Q: Transparency page presentation?**
A: Rendered as a self-contained static HTML page (`docs/transparency.html`) generated by
`scripts/render_transparency.py`. No runtime web server or external stylesheet dependencies required.

## 2026-10-02 — Milestone 2 (Collection & Normalization)

**Q: Deduplication and syndication tracking?**
A: `Deduplicator` (`src/newsx/deduplication.py`) computes normalized n-gram Jaccard similarity.
Exact duplicates ($\ge 0.95$ similarity) set `duplicate_of`; syndicated wire copy ($\ge 0.70$ similarity)
set `republished_from`. This links republishing chains and prevents inflating independent-origin counts.

**Q: Quote boundary preservation in passage segmentation?**
A: `Normalizer` (`src/newsx/normalizer.py`) tracks quotation state (`"`, `“`, `”`, `'`, `‘`, `’`) and
protected abbreviations (`U.S.`, `Dr.`, `Gov.`, `vs.`, `e.g.`) so complete quotations with speaker attributions
remain intact as single coherent sentence passages.

**Q: Raw storage & audit trail architecture?**
A: Storage uses SQLite (`data/newsx.db`) for relational queries and indexing, accompanied by immutable
append-only JSONL files (`data/audit.jsonl`) and archived raw payloads (`data/raw/`) indexed with SHA-256 hashes.

## 2026-10-02 — Milestone 3 (Triage — Article & Passage Classification)

**Q: Hierarchical decision ladder for article triage?**
A: `ArticleTriager` (`src/newsx/triage.py`) prioritizes explicit signals:
1. URL / Section placement (`/opinion`, `/commentisfree`, `/analysis`, `/sponsored`)
2. Headline prefixes (`Opinion:`, `Analysis:`)
3. Byline roles (`Columnist`, `Analysis desk`, `Brand Studio`)
4. Content markers (`in my view`, `must be resisted`, `signals a`)
Default fallback: `reporting`.

**Q: Passage-level fact-base routing rule?**
A: Per spec §6, `feeds_fact_base` is `True` if and only if `article_type == reporting` AND
`passage_type in {observed event, quantitative, attributed statement}`.
Opinion, analysis, sponsored, and satire articles have `feeds_fact_base = False` across all passages,
retaining them strictly as framing context in separate labeled sections. Quantitative statements without
direct quotes are prioritized over secondary attribution verbs to prevent misclassifying pure metric sentences.

## 2026-10-02 — Milestone 4 (Claim Extraction — Atomic Claims & Provenance)

**Q: Extractive-first span anchoring constraint?**
A: `ClaimExtractor` (`src/newsx/extractor.py`) computes character offset bounds `[span_start, span_end]`
within the source passage. If candidate text cannot be verified as an exact substring of the passage,
`status = ClaimStatus.REJECTED` and the proposition is discarded from downstream aggregation.

**Q: Dual-layer attribution extraction?**
A: Per spec §3.2, every attributed statement produces two separate claims:
1. Assertion Layer: That the statement was made (`claim_type = statement`, `attribution_speaker = speaker`, `attribution_anonymous = bool`).
2. Content Layer: What was said (`claim_type = quantity | event | causal`).
Anonymous attributions (`officials`, `sources`, `critics`) are explicitly flagged `attribution_anonymous = True`.

**Q: Provenance chain representation?**
A: Stored as a 3-element array `[source_id, item_id, passage_id]` on each claim record, ensuring 100%
traceability to raw text and source profile.

**Q: Swappable model caching?**
A: All model calls go through `BaseModelClient` (`src/newsx/models.py`), hashed with SHA-256 and
cached on disk (`data/cache/`) with temperature=0.0 and seed=42 for reproducible offline evaluation.

## 2026-10-02 — Milestone 5 (Neutralization — Neutral Rewrites & Meaning Checks)

**Q: Reversible change tracking design?**
A: `Neutralizer` (`src/newsx/neutralizer.py`) attaches a list of `ChangeRecord` objects to each claim
capturing `original_span`, `replacement`, `category` (intensifier, emotive_adjective, charged_verb, loaded_label),
and normative `rationale`. The user can always inspect original wording and exact removals (spec §3.4).

**Q: Meaning-preservation verification and fallback?**
A: `MeaningChecker` validates that all numbers, unit symbols, named entities, and dates are strictly preserved.
If any factual discrepancy or entity loss occurs, the claim reverts to `original_wording`, sets
`neutralized_wording = None`, and assigns `status = ClaimStatus.FLAGGED` with an explanation recorded in audit logs.

**Q: Factual emotion preservation whitelist?**
A: Terms where emotional severity is itself the checkable fact (e.g., `hospitalized`, `injured`, `killed`,
`died`, `evacuated`, `arrested`, `fined`) are protected via `factual_whitelist` and never stripped.

## 2026-10-02 — Milestone 6 (Clustering & Corroboration — Syllables, Contradictions, & Tiers)

**Q: Independent Origin Counting & Syndication Collapse?**
A: `IndependentOriginResolver` (`src/newsx/corroboration.py`) traverses syndication and republishing chains (`republished_from`, `duplicate_of`) to collapse syndicated wire copies to their single origin item. Corroboration counts distinct independent origins rather than raw article volume, preventing wire propagation from inflating claim credibility.

**Q: Semantic Slot Clustering & Claim Equivalence?**
A: `ClaimMatcher` groups atomic claims into `ClaimCluster` instances using semantic slot intersection (matching `subject`, `predicate`, `object`, `value`, `unit`) combined with word token Jaccard similarity ($\ge 0.60$), ensuring claims describing the identical real-world fact are clustered across sources.

**Q: Direct Contradiction Detection?**
A: `ContradictionDetector` identifies conflicting claims within clusters when:
1. Numeric divergence occurs on identical metric slots (e.g., different values/quantities for the same entity).
2. Direct polarity or status negation occurs without chronological reconciliation.
When a contradiction is flagged, both claims are cross-referenced in `contradiction_ids` and assigned `ConfidenceTier.DISPUTED`.

**Q: Confidence Tiering Logic?**
A: `ConfidenceTierEngine` assigns tiers based on strict hierarchy:
- Tier 1 (`PRIMARY_CONFIRMED`): Verified by $\ge 1$ Tier 1 Primary origin (official filing, government agency report, primary witness record).
- Tier 2 (`INDEPENDENTLY_CORROBORATED`): Corroborated by $\ge 2$ independent Tier 2/3 origins with no contradictions.
- Tier 3 (`SINGLE_SOURCE`): Supported by exactly 1 independent origin with no contradictions.
- Tier 4 (`DISPUTED`): Direct numeric or polarity contradiction detected across sources.
- Tier 5 (`UNVERIFIED_OR_RETRACTED`): Retracted or unsubstantiated single anonymous assertion.

## 2026-10-02 — Milestone 7 (Presentation — Event Briefs with Full Drill-Down)

**Q: Structured Brief partition & ranking policy?**
A: `BriefGenerator` (`src/newsx/brief.py`) partitions claims into four distinct, non-overlapping sections:
1. Core Verified Facts: Tier 1 (`PRIMARY_CONFIRMED`) and Tier 2 (`INDEPENDENTLY_CORROBORATED`), ranked with Tier 1 first followed by independent origin count descending.
2. Disputed Points: Tier 4 (`DISPUTED`) paired contradictions displayed side-by-side with speaker/outlet attribution and verbatim source quotes.
3. Single-Source Context: Tier 3 (`SINGLE_SOURCE`) isolated from core consensus to prevent uncorroborated dominance.
4. Known Unknowns & Coverage Notices: Tier 5 unverified assertions, missing primary sources, and diversity quota deficiencies.

**Q: Multi-format rendering and full drill-down traceability?**
A: `MarkdownBriefRenderer`, `HtmlBriefRenderer`, and `ConsoleBriefRenderer` (`src/newsx/presenter.py`) provide complete provenance drill-downs:
- Every bullet embeds supporting source IDs, independent origin counts, source URLs, and passage references.
- Neutralization adjustments display original wording, exact span replacements, categories, and rationales.
- Interactive HTML briefs include collapsible `<details>` drawers and color-coded tier badges for transparent auditing.

## 2026-10-02 — Milestone 8 (Continuous & Multi-Event Pipeline — Updates, Retractions & Diffing)

**Q: Incremental event routing and token matching?**
A: `EventMatcher` (`src/newsx/continuous.py`) computes normalized token and entity overlap between candidate incoming articles and active event clusters ($\ge 0.15$ threshold), routing updates to existing events without full re-clustering of unrelated events.

**Q: Dynamic confidence tier transitions?**
A: `ContinuousEngine` recalibrates cluster confidence whenever an event's claim graph changes:
- Arrival of a 2nd independent secondary source elevates a single-source claim from `Tier 3 (SINGLE_SOURCE)` to `Tier 2 (INDEPENDENTLY_CORROBORATED)`.
- Arrival of a Tier 1 primary official report/filing elevates claims to `Tier 1 (PRIMARY_CONFIRMED)`.
- Conflicting numeric or action claims transition the affected propositions to `Tier 4 (DISPUTED)`.

**Q: Publisher retraction and correction propagation?**
A: When a publisher issues a retraction notice (`ContinuousEngine.handle_retraction`), affected claims are immediately marked `ClaimStatus.REJECTED`. The engine purges retracted claims from cluster consensus, decrements independent origin counts, and recalculates downstream event briefs, logging the retraction rationale across `version_history` and `audit_log`.

**Q: Structured Brief version diffing?**
A: `compute_brief_diff` compares successive brief versions ($v1.0 \rightarrow v1.1$), explicitly capturing `new_core_facts`, `promoted_facts` (tier upgrades), `new_disputes`, `retracted_claims`, and a human-readable `summary_of_changes`.

## 2026-10-02 — Milestone 9 (Evaluation & Golden Dataset Validation — Benchmark Suite & Production Readiness)

**Q: Unified regression harness design?**
A: `scripts/evaluate_all.py` runs all sub-evaluations (M0 through M8) in a single deterministic pass, asserting quantitative threshold compliance on Kappa agreement ($\ge 0.85$), triage accuracy ($\ge 90\%$), span grounding F1 ($= 1.0$), neutralization reversibility ($100\%$), corroboration hierarchy, presentation drill-down links, and continuous streaming diffs.

**Q: Production readiness & Zero Recurring Cost?**
A: The system executes entirely with local open-weight and deterministic extractor clients (`DeterministicExtractorClient`, `OllamaModelClient`) without incurring paid API calls or cloud lock-in. Full provenance is recorded in SQLite and immutable JSONL audit streams.
